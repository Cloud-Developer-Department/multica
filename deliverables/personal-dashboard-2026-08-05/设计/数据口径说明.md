# 数据口径说明：个人用量看板

> 文档编号：CALC-CLO-211
> 版本：v1.0（2026-08-05）
> 需求基线：CLO-206 §四（指标口径）/ §六（数据来源）/ §七（边界异常）
> 本文件是所有指标计算的**唯一权威定义**；前后端实现若与本文冲突，以本文为准。

---

## 1. 指标归属（initiator_user_id）

- 所有个人指标按任务发起人归属：`agent_task_queue.initiator_user_id`。
- **含自动任务 / autopilot**：autopilot 触发的任务归属到配置该 autopilot 的用户（即该任务行的 `initiator_user_id`），算在配置人头上（CLO-206 §二.6 / §四）。
- `initiator_user_id` 为 NULL 的历史/异常行：不归属到任何个人，**不计入任何个人指标与排行榜**（对团队聚合也不贡献）。
- 后端从登录会话取当前用户（`X-User-ID`），强制 `initiator_user_id = 当前用户` 过滤；不接受前端传 `user_id`。

## 2. 统计范围

- 只统计该用户发起的**终态任务**：
  - 终态 = `status IN ('completed', 'failed')`。
  - `queued / dispatched / running / cancelled` 一律不计入（cancelled 不是完成也不是失败，CLO-206 成功率口径未包含）。
- token / 成本 = 终态任务关联的 `task_usage` 记录（`task_usage.task_id = agent_task_queue.id`）。
- 时间窗口按**任务完成时刻 `completed_at`** 落入窗口判定（与现有看板 token 成本窗口一致，均锚定终态时间）。
  - 【补充】CLO-206 未明确窗口锚点，采用与现有看板一致的 `completed_at` 锚定，避免运行中任务在切换窗口时跳变。

## 3. Token 组成

```
token_total = input_tokens
            + output_tokens
            + cache_read_tokens
            + cache_write_tokens
```

- 对窗口内该用户所有 `task_usage` 行求和（`provider/model` 不限，所有行累加）。
- 各分量 `token_input / token_output / token_cache_read / token_cache_write` 也分别在 summary 中返回。

## 4. 成本换算（USD → ¥）

### 4.1 成本计算职责

**服务端只回原始拆分，USD / CNY 由前端计算**（与现有工作区看板一致，前端已有价目表与成本逻辑）：

```
cost_usd  = Σ[ 权威 cost_usd_ticks（1e-10 USD）/ 1e10 ]
          + Σ[ 估算(未上报行的 token 分量 × 价目表单价) ]
cost_cny  = cost_usd × /api/dashboard/rates 的 rate
```

- 权威：`task_usage.cost_usd_ticks` 非空的行（供应商上报价）。
- 估算：`cost_usd_ticks` 为 NULL 的行，按其 token 分量 × 静态价目表单价计算（per-million）。
  - 估算公式（价目表各单价为 `$/1M tokens`）：
    - `input × input_per_m / 1e6`
    - `+ output × output_per_m / 1e6`
    - `+ cache_read × cache_read_per_m / 1e6`
    - `+ cache_write × cache_write_per_m / 1e6`
- 汇总：`total_cost_usd = Σ 单行 USD`（窗口内该用户全部 task_usage）；`total_cost_cny = total_cost_usd × 生效汇率`。
- 成本展示统一人民币 ¥，两位小数；USD 作为参考（tooltip）一并展示。
- 某模型未匹配价目表：其 token 照常计入 token 指标；成本按 `0` 计，前端归入「未定价」分类展示（不阻塞、不 500）。

### 4.2 权威成本的背景

- 参考迁移 `213_task_usage_authoritative_cost`：xAI 等供应商按请求返回 `_meta.usage.costUsdTicks`（1e-10 USD），聚合行的 token 无法还原分档价，故权威价优先；未上报的行沿用静态价目表估算。历史行 `cost_usd_ticks` 恒为 NULL，全部估算。
- 传输形态：接口 1/2/3 返回 `cost_usd_ticks` + `uncosted_{input,output,cache_read,cache_write}_tokens`（见 API 契约 §0.3）。

### 4.3 静态价目表

- **成本计算侧（前端）**：`packages/views/runtimes/utils.ts` —— 个人看板成本换算统一用它。
- 服务端价目表 `server/internal/metrics/pricing.go`（`PriceForModelAlias`）用于 Prometheus 等指标估算，非本看板成本来源。
- **两表必须保持同步**；新增模型时两端同改。未匹配模型成本为 0，前端标记「未定价」。

### 4.4 实时汇率与降级

| 项 | 定义 |
| --- | --- |
| 外部接口 | 服务端配置的实时汇率 API（USD→CNY），HTTP 拉取 |
| 缓存 | 汇率缓存 TTL ≤ 10 分钟；TTL 内复用，避免高频打外部接口 |
| 降级 | 拉取失败（网络错误 / 非 2xx / 响应非法）→ 使用配置默认值（如 7.2） |
| 默认值配置 | 建议环境变量 `MULTICA_DASHBOARD_FX_DEFAULT_CNY`（默认 `7.2`）；未配置且拉取失败才视为不可用 |
| 生效汇率 | 当前缓存/降级后的汇率，`/rates` 返回 `rate` + `source` + `updated_at` |
| 标注 | 看板标注「汇率更新于 xx:xx」；降级时「汇率更新于 xx:xx（默认汇率）」 |

- **一致性**：前端统一从 `/rates` 取一次生效汇率用于全部 ¥ 换算，保证「成本 ÷ 展示汇率」一致。
- 汇率失败且无默认值 → `/rates` 返回 500（异常态），前端成本卡按异常态处理。

## 5. 成功率 / 失败率

```
success_rate = completed_count / (completed_count + failed_count) × 100
failure_rate = failed_count      / (completed_count + failed_count) × 100
```

- 均为 0–100，保留 1 位小数。
- **无终态任务**（completed+failed = 0）时：`success_rate` / `failure_rate` 为 `null`，前端显示 `-`（CLO-206 §四 / §七）。
- `trend`/逐桶的失败率：某桶无终态任务时该点为 `null`。

## 6. 运行时长

```
run_seconds = Σ (completed_at - started_at)   （终态任务，且两者均非空）
```

- 仅计入 `status IN ('completed','failed')` 且 `started_at`、`completed_at` 均非空的任务。
- 缺任一时戳的任务：**不计入时长**（也不计入耗时分布），但计入任务数。
- 单位为秒（整数）。
- 逐桶聚合（runtime-trend）：按任务 `completed_at` 落入对应小时/天桶后，对该桶内任务的时长求和；`task_count` 为该桶计入时长的任务数。

## 7. 耗时分布分桶定义

单任务耗时（`completed_at - started_at`，秒）按以下区间分桶（**下含上不含**）：

| bucket | 区间（秒） | 展示 |
| --- | --- | --- |
| `<1m` | [0, 60) | `<1分钟` |
| `1-5m` | [60, 300) | `1-5分钟` |
| `5-15m` | [300, 900) | `5-15分钟` |
| `15-30m` | [900, 1800) | `15-30分钟` |
| `>30m` | [1800, ∞) | `>30分钟` |

- 只统计满足 §6 时戳条件的终态任务；任务按其 `completed_at` 落入窗口。
- 接口恒返回 5 桶，空桶 `count=0`。

## 8. 排行榜口径（rank 接口）

### 8.1 成员集合

- `total_members` = 窗口内**有 ≥1 条终态任务**（按 §2 归属口径，即 `initiator_user_id` 非空）的成员数，**含本人**。
- 无终态任务的成员不进入排行榜集合（CLO-206：共 M 人指参与消耗的人）。

### 8.2 本人名次与超过百分比

- 每人得分 = 该成员窗口内 `token_total`。
- `rank` = **竞争式排名（competition ranking）**：`1 + (# 成员得分 > 本人得分)`；得分相同者共享名次（如 3 人并列第 2，下一个为第 5）。
- `exceed_pct` = `(# 成员得分 < 本人得分) / (total_members - 1) × 100`，保留 1 位小数。
  - `total_members ≤ 1` → `exceed_pct = 0`。
  - 本人无终态任务 → `rank = null`、`exceed_pct = null`（前端「暂无排名」）。
- **任何情况下响应中不含他人得分/他人明细**。

### 8.3 团队聚合（匿名）

- `team_avg_tokens` = `Σ 成员 token / total_members`；`total_members = 0` → `null`。
- `team_median_tokens` = 成员 token 的中位数：
  - 成员数 n：将得分升序排列，n 为奇数取中间项；n 为偶数取中间两项平均值（保留整数）。
  - `total_members = 0` → `null`。
- 聚合含本人但不含 `initiator_user_id` 为 NULL 的行。

## 9. 示例：成本 + 排名计算演练

```
窗口 week，成员 { A, B, C, 我 }（4 人，均有终态任务）

各人 token_total：A=60M, B=30M, C=30M, 我=48M
→ 排名（降序）：A(1), 我(2), B(3), C(3)      // 并列共享名次，next=4 无意义（4 人）
→ rank=2, total_members=4
→ exceed_pct = (#得分<48M=2) / (4-1) × 100 = 66.7
→ team_avg_tokens = (60+30+30+48)M / 4 = 42M
→ 中位数：30,30,48,60 → (30+48)/2 = 39M

成本：B 行 cost_usd_ticks=1.8e10（=$1.8 权威）+ 其余全估算……
→ total_cost_usd = 18.3521
→ 生效汇率 7.2 → total_cost_cny = 132.14
```

## 10. 边界与异常（口径层面）

| # | 场景 | 口径 |
| --- | --- | --- |
| B1 | 窗口内本人无终态任务 | 所有数值为 0；`success_rate`/`failure_rate`=`null`；`rank`/`exceed_pct`=`null` |
| B2 | 窗口内全工作区无人有终态任务 | `total_members=0`；人均/中位数 `null`；榜单显示空 |
| B3 | 仅本人有终态任务 | `rank=1, total_members=1, exceed_pct=0`；人均=中位数=本人值 |
| B4 | 任务缺 started_at/completed_at | 计入任务数；不计入时长/耗时分布 |
| B5 | 某任务 token 全为 0 | 正常计入任务数、成本 0 |
| B6 | `cost_usd_ticks` 全空 | 成本全为静态估算；仍可计算 |
| B7 | 汇率接口失败 | 用默认汇率（7.2），`source=default`；成本仍展示 |
| B8 | 汇率接口失败且无默认值 | 成本相关接口 500 |
| B9 | 模型未匹配价目表 | token 计入；成本 0；前端归入「未定价」分类 |
| B10 | `failure_reason` 为空/缺失的失败任务 | 归入 `unclassified` 桶（复用现有看板约定） |
| B11 | 失败任务无 `completed_at`（如 queued_expired） | 若在窗口内照常计入失败与错误类型；不计入时长/耗时分布（无 started_at/completed_at 双时间戳） |

> B11 说明：`queued_expired` 类失败无 started_at，但明确是失败（CLO-206 §四 耗时分布只统计有时戳任务，错误类型口径不设时戳门槛），沿用现有 failures 查询的"失败必入错误类型"约定。

## 11. 数据源与实现约束

- 个人统计**不走 `task_usage_hourly`**（无用户维度），从 `task_usage` 直查 + `agent_task_queue.initiator_user_id` 关联聚合（CLO-206 §六说明；本地规模足够）。
- 建议加索引：`agent_task_queue(initiator_user_id, status, completed_at)` 以支撑个人窗口聚合；`task_usage(task_id)` 已有。
- 时间切桶在服务端按 `tz` 计算；桶起点统一输出为 UTC RFC3339（前端转本地）。
