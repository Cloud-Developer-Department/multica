# PRD：开发者个人用量看板（MVP）

> 文档编号：PRD-CLO-211
> 状态：**待 Leader 审核**（审核通过后进入 UI/UX 阶段）
> 版本：v1.0（2026-08-05）
> 需求基线：CLO-206《数据监控看板优化 —— 个人维度用量看板（MVP）》（需求方已确认，**唯一标准，禁止私自变更**）
> 本文档唯一可信源。若与任何历史文档冲突，以本文档 + CLO-206 基线的组合为准；对基线的任何解释均以本节《需求基线解读》为口径。

---

## 1. 需求背景与目标

现有数据监控看板（`/{slug}/dashboard`）偏平台运营视角（评论热度 / 项目进度 / 运行时状态 / Issue 状态分布），不是开发者关心的重点，且缺少开发者最关心的用量数据（token 消耗、成本）。

本次将 `/{slug}/dashboard` 改造为**开发者个人用量看板**：

- 开发者打开看板默认看到"我自己"的消耗情况；
- 含团队内自己的排名（**他人消耗数字一律隐藏**）；
- 成本以人民币（¥）实时汇率展示；
- 目标用户：全体开发者，默认个人维度；
- 部署方式：本地部署（`C:\multica-deploy\multica`，分支 `Equipment_Department_Exploration`）；
- 数据策略：先做功能，最后统一造演示数据。

## 3. 时间维度口径

### 3.1 取值

| 取值 | 含义 | 窗口定义（查看者本地时区） |
| --- | --- | --- |
| `today` | 今天 | 今日 00:00:00 → 当前时刻 |
| `week` | 本周 | 本周一 00:00:00 → 当前时刻 |
| `month` | 本月 | 本月 1 日 00:00:00 → 当前时刻 |

- **默认本周（`week`）**。
- 周起点定义：**周一 00:00:00**（本地时区）。【补充】CLO-206 未指定周起点，按中文语境惯例取周一，研发如有异议可在评审提出。
- 所有"当前时刻"为后端处理请求的时刻；同一请求内所有模块使用同一窗口，保证全页一致。
- 时区：优先 `?tz=<IANA>`，缺省取用户已存时区，兜底 UTC（与现有看板 `resolveViewingTZ` 一致）。

### 3.2 切换行为

- 顶部时间切换为 **今天 / 本周 / 本月** 三段式控件，默认选中"本周"。
- 切换后**全页所有模块跟随切换、并行全量重查**（8 个接口并发请求）。
- 切换期间：各模块卡片保留上一窗口数据并展示骨架屏（loading），不整页白屏；数据返回后原位更新。
- 切换不改变已选图表切换项（如 Token/成本、模型分布按 token 等）。

## 4. 页面结构与布局

├────────────────────────────────────────────────┤
│ ② 我的排名卡（全宽）                           │
│   第 N 名 / 共 M 人 · 超过 X% 成员              │
│   团队人均 token · 团队中位数 token             │
├────────────────────────────────────────────────┤
│ ③ Token/成本趋势图（折线，可切换）              │
├────────────────────────────────────────────────┤

├────────────────────────────────────────────────┤

## 5. 各模块详细设计

> 通用卡片状态约定（所有模块一致）：`loading`（骨架屏）→ `error`（模块级错误 + 重试按钮）→ `empty`（空态文案）→ 正常渲染。任一模块异常不影响其他模块渲染；全部模块异常时整页展示错误态 + 重新加载。

### 5.1 模块① KPI 卡（我的数据）

- **数据来源**：`/summary`
- **展示**：5 张 KPI 小卡
  - **Token 消耗**：总数（千分位），单位 `tokens`。数值 ≥ 1e6 时可展示为 `X.XX M`。【补充】前端展示精度由 UI/UX 决定，接口始终返回精确整数。
  - **成本（¥）**：`¥` + 两位小数人民币；卡片下方小字标注 **汇率更新于 xx:xx**（来源 `/rates`）。
  - **任务数**：终态任务总数（completed + failed）。
  - **运行时长**：总时长，按秒→可读格式（如 `3h 40m`）由前端格式化；接口返回秒数。【补充】展示格式由 UI/UX 确定。
  - **成功率**：百分比（1 位小数），无终态任务时显示 **`-`**。
- **空态**：Token=0 且 任务数=0 时，KPI 区整体展示空态「**本周暂无消耗**」（文案随当前范围切换：今天/本周/本月暂无消耗），各卡数值展示 `0` 或 `-`。
- **异常**：接口失败时 5 卡均展示 `-`（MISSING）+ 模块级错误重试。

### 5.2 模块② 我的排名卡

- **数据来源**：`/rank`
- **展示**：
  - 主文案：`本周你排 第 N 名 / 共 M 人，超过 X% 成员`（范围随切换：今天/本周/本月你排…）。
  - 附团队聚合（匿名聚合值，**不返回、不展示任何他人消耗数字**）：
    - `团队人均 token`：团队人均消耗；
    - `团队中位数 token`：团队消耗中位数。
  - 可选展示：`我的 token`（本人数值，允许展示）。
- **边界**：
  - 本人无终态任务 → 显示「**暂无排名**」，不展示"第 N 名"。
  - 只有自己（M=1）→ 正常显示 `第 1 名 / 共 1 人`，超过百分比为 0。
  - M=0（本工作区窗口内无人有终态任务）→ 团队人均/中位数不展示（`-`）。
- **口径**：见数据口径文档 §8（含并列排名、超过百分比定义）。

### 5.3 模块③ Token/成本趋势图

- **数据来源**：`/trend`（接口一次返回 `tokens` 与 `cost_usd/cost_cny` 两组值，切换仅为前端行为，不重查）
- **图表**：折线图。**切换项：Token / 成本**，默认 Token；切换即时生效，不发请求。
- **分桶粒度**：`today` → 按小时（当日 0 点至当前小时）；`week`/`month` → 按天（周一/1 号起至今天）。
- **空桶补零**：无数据桶补 `0`，保证折线连续。
- **空态**：「**暂无趋势数据**」（全桶全 0 时）。
- **成本口径**：折线上成本展示人民币 ¥；tooltip 可同时展示 USD 参考值【补充】。

### 5.4 模块④ 模型分布

- **数据来源**：`/models`
- **图表**：饼图 / 横向占比条形图，**切换项：Token / 成本**（默认 Token，即时切换，不重查）。
- **展示**：每个模型：模型名、token 占比（%）与数值、成本占比（%）与数值（¥）。未匹配价目表的模型展示为「**未定价 / unmapped**」分类（仍展示 token 消耗，成本按 0 计），见数据口径文档 §4.3。
- **排序**：按 token 消耗降序。
- **空态**：「**暂无模型数据**」。

### 5.5 模块⑤ 耗时分布（直方图）

- **数据来源**：`/duration`
- **图表**：单任务耗时直方图，固定 5 个分桶（接口恒返回 5 桶，空桶计数 0）：

| 分桶 | 区间（秒，含下界不含上界） |
| --- | --- |
| `<1m` | [0, 60) |
| `1-5m` | [60, 300) |
| `5-15m` | [300, 900) |
| `15-30m` | [900, 1800) |
| `>30m` | [1800, ∞) |

- **口径**：仅计入有 `started_at` 与 `completed_at` 的终态任务（completed + failed，失败任务也消耗时长），见数据口径文档 §6/§7。
- **空态**：「**暂无耗时数据**」。

### 5.6 模块⑥ 总运行时长趋势

- **数据来源**：`/runtime-trend`
- **图表**：折线。`today` 按小时、`week`/`month` 按天（与模块③粒度一致）。
- **空桶补零**。tooltip 同时给出该桶 `任务数`。
- **空态**：「**暂无运行时长数据**」。

### 5.7 模块⑦ 失败率趋势

- **数据来源**：`/errors` 的 `trend` 部分
- **图表**：折线，纵轴失败率（%）。`today` 按小时、`week`/`month` 按天。
- **口径**：某桶无终态任务时该点失败率为空（`null`，不绘制断点）。窗口整体失败率无终态任务时为 `-`。
- **空态**：「**暂无失败数据**」。

### 5.8 模块⑧ 错误类型分布

- **数据来源**：`/errors` 的 `types` 部分（**复用 taskfailure 分类**，21 个规范值 + `unclassified` 兜底，见数据口径文档 §4.4 / `server/pkg/taskfailure`）
- **图表**：横向条形 TOP 列表：错误类型、失败次数、占比（%）。
- **排序**：按失败次数降序。
- **空态**：无失败任务时「**暂无错误类型数据**」。

## 6. 全局交互规则

1. **时间切换**（今天/本周/本月）：切换即全量重查（§3.2）。
2. **图表切换**（Token/成本、token/成本、成功率/失败率等）：前端即时切换，不触发请求（趋势与模型接口已一次返回所需双序列）。
3. **手动刷新**：工具栏提供刷新按钮；重复点击节流（≥2s）。【补充】MVP 不纳入自动刷新轮询，后续按需迭代；CLO-206 未要求自动刷新。
4. **汇率状态**：页面加载时请求 `/rates` 一次（60s 内复用缓存），在工具栏或成本卡标注「**汇率更新于 xx:xx**」；降级为默认值时标注「**汇率更新于 xx:xx（默认汇率）**」。
5. **错误降级**：单模块失败仅该模块显示错误态 + 重试按钮；≥ 3 个模块同时失败视为后端不可达，整页错误态。
6. **空态**：各模块独立空态文案（§5、§7 文案清单）。
7. **权限**：接口服务端强制当前登录用户，前端不传 `user_id`（§9）。

## 7. 正常 / 边界 / 异常场景清单

| # | 场景 | 表现 |
| --- | --- | --- |
| N1 | 本人窗口内有消耗 | 各模块渲染真实数据 |
| N2 | 排行榜有他人 | 仅展示名次/总人数/超过%/人均/中位数，无他人数字 |
| N3 | 汇率接口正常 | 成本按实时汇率换算，标注「汇率更新于 xx:xx」 |
| E1 | 本人无任何终态任务 | KPI 显示 0/`-`；排名显示「**暂无排名**」；其余模块空态文案 |
| E2 | 本人无消耗但窗口内有任务 | 排名正常（第 1 名/共 M 人或更靠后），KPI token/成本为 0 |
| E3 | 排行榜只有自己 | 显示「第 1 名 / 共 1 人」，超过 0%，人均=中位数=本人值 |
| E4 | 工作区窗口内无人有终态任务 | 排名卡只显示「暂无排名」或「共 0 人」态，人均/中位数不展示 |
| E5 | 汇率接口拉取失败 | 降级配置默认值（如 7.2），成本仍展示，标注「汇率更新于 xx:xx（默认汇率）」 |
| E6 | 某模型未在价目表 | token 正常展示，成本按 0 计，归入「未定价」分类，不阻塞接口 |
| E7 | 单任务缺 started_at/completed_at | 该任务不计入运行时长与耗时分布，计入任务数 |
| E8 | `range` 非法/缺失 | 回退默认 `week`，不报错 |
| E9 | `tz` 非法/缺失 | 回退用户时区，再兜底 UTC，不报错 |
| E10 | 用户未登录 | 401，前端跳转登录 |
| E11 | 非工作区成员访问 | 403，拒绝访问 |
| E12 | 服务端聚合异常 | 500，单模块错误态 + 重试 |
| E13 | 时间切换并发竞态 | 以最后一次切换为准，过期响应丢弃（前端以请求序号/AbortController 处理） |
| E14 | 空桶 | 趋势/直方图补 0，不出现数据断层 |
| E15 | token/成本为 0 但任务数>0 | 正常渲染任务数与 0 消耗，不触发「暂无消耗」空态（空态条件是 token=0 且任务数=0） |

## 8. 移除模块确认

以下模块**不再展示**（CLO-206 §二.5）：

- Issue 状态分布
- 项目进度
- 评论热度
- 运行时状态

> 对应的 `GET /api/dashboard/issue-distribution|activity|comments|completion` 及 `GET /api/runtimes` 在原页面不再消费；接口是否下线由后端团队评估（可保留兼容，前端不再调用）。

## 9. 权限与数据安全（强制）

1. **个人接口**：服务端从登录会话取当前用户，**强制按当前用户过滤**，**不接受前端传 `user_id`**（传了也忽略）。用户身份来源：登录态 → `X-User-ID` 头（服务端鉴权中间件注入，不可伪造）。
2. **排行榜接口**：仅返回「我的名次 / 总人数 / 超过百分比 / 团队人均 / 团队中位数」，**不返回任何他人明细**（不含他人 token、成本、名次列表）。
3. **前端排行榜卡片**：不展示他人消耗数字；接口设计上也不返回，杜绝前端拿到后误展示。
4. 所有接口沿用工作区成员校验（`/{slug}/dashboard` 所在路由组）。

## 10. 非目标（MVP 范围外，后续迭代）

- 多工作区汇总、跨团队对比。
- 按项目 / 按智能体下钻。
- 成本预算、告警、导出。
- 自动刷新轮询。
- 每任务级明细列表。

## 11. 验收标准（对应 CLO-206 §八）

1. 8 个接口按数据口径文档返回正确；空态/异常态全覆盖。
2. 页面真实数据渲染；排行榜不泄露他人数字。
3. 汇率实时拉取 + 降级逻辑均验证通过。
4. 移除的 4 个模块不再展示。
5. 造演示数据后本地部署完整呈现（前端重建 + 服务重启）。
