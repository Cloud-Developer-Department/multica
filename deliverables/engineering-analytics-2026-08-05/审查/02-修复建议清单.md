### P0-01 列表接口响应包裹层解析错误（阻塞）

**问题**：后端 A3/A5/B3/B6 返回 `{"items": [...]}` / `{"points": [...]}`，前端客户端按裸数组解析，`parseWithFallback` 恒回退 `[]`。

**文件/行**：
- `packages/core/api/client.ts:1867-1872`（`getAnalyticsTopMembers`）
- `packages/core/api/client.ts:1893-1898`（`getAnalyticsAdoptionTrend`）
- `packages/core/api/client.ts:1941-1946`（`getAnalyticsTopAgents`）
- `packages/core/api/client.ts:1987-1992`（`getAnalyticsBlockers`）
- `packages/core/api/schemas.ts:2114-2119`（四个 ListSchema 目前为 `z.array(...)`）

**建议**：
- 方案 A（推荐，改动小）：客户端取 `raw.items` / `raw.points` 后再用现有数组 Schema 解析，即
  `const body = raw as { items?: unknown }; parseWithFallback<AnalyticsTopMember[]>(body.items, AnalyticsTopMemberListSchema, [], ...)`。
- 方案 B：将 4 个 Schema 改为 `z.object({ items: z.array(...) })` / `z.object({ points: z.array(...) })`，客户端返回 `result.items` / `result.points`。
- 同步检查视图消费：`tab1-adoption.tsx:150,203,209`（top-members、adoption-trend）、`tab2-agent.tsx:57,179`（blockers）。

### P1-05 Tab4「部署频率」KPI 单位换算错误

**文件/行**：`packages/views/analytics/tab4-dora.tsx:84`。

```ts
value: formatDurationEn(d?.deploy_frequency_weekly != null ? d.deploy_frequency_weekly * 86400 : null),
```

**问题**：`deploy_frequency_weekly` 语义为「次/周」（D2 契约字段），直接 `×86400` 当成秒转时长输出（如 4.5 次/周 → "4天12时"）无物理意义；应为「次/周」文案（如 `4.5次/周`）或按「平均部署间隔 = 7天×86400 ÷ freq」换算。

**建议**：KPI 直接展示 `deploy_frequency_weekly`（单位 次/周，用 `toFixed(1)` + 单位文案），或改用平均间隔口径并明确标注。
