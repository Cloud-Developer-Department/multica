## 0. 总则

1. **一期指标全部基于 Multica 本地库现有数据可算**（`issue` / `agent_task_queue` / `comment` / `skill` / `agent_skill` / `member` / `user` / `task_usage_hourly` / `activity_log`）。凡本地库无法支撑的口径，一律标注数据源接入阶段。
2. **全局口径**：默认不做按部门维度；部门维度切片为**条件功能**（LDAP/IDP 或手动部门映射接入后启用，见 §1.5）。
3. **时间窗口统一语义**（与现有看板 `resolveViewingTZ` 一致）：
   - `days` 默认 30，最大 365。
   - 按查看者时区 `tz`（IANA）切日/切小时；非法或缺省回退用户已存时区 → UTC。
   - 日界：`tz` 本地 00:00。
4. **空值语义**（全平台统一）：
   - `null`：指标在窗口内无有效分母或不可计算（如无 Agent 时的渗透率、无 Blocker 时的响应时长、无部署时的 MTTR）。前端渲染 `-`。
   - `[]`：该维度无数据，前端渲染空态文案。
   - 缺省字段：仅用于向后兼容的扩展字段；契约声明的字段一律返回。
   - `0`：有明确语义的数值零，**不是空态信号**。
5. **外部数据源状态**（v2.0 新增）：G/D/L 系列接口顶层 `source_status`（见 API 契约 §0.7）统一表达「数据源未接入/就绪」；`ready=false` 时业务字段按各自语义返回 `null`/`[]`/`0`。
6. 旧个人看板（CLO-206/CLO-211）的成本、人民币汇率、模型价格等口径**不再沿用**，本平台不展示成本类指标（成本留在现有 Usage 看板）。
7. 口径如需调整，走 Leader 确认流程（见 PRD §10），禁止研发擅自改口径。

## 1. 模块 2.1 活跃度与渗透（全局口径 + LDAP 扩展）

### 1.1 活跃热力图（v1.0 保留）

同 v1.0：人均 Issue 处理量（创建量）、活跃天数、活跃时段。口径不变。

### 1.2 Agent 渗透率（v1.0 保留）

同 v1.0：分配占比、Issue 覆盖率。口径不变。

### 1.3 活跃用户占比 DAU/MAU（v1.0 保留）

同 v1.0。LDAP 接入后分母可加部门过滤。

### 1.4 用户生命周期（v2.0 新增，LDAP/IDP 依赖）

#### 1.4.1 入职开通率

- **定义**：窗口内「新入职员工中已在平台开通账号的比例」。
- **分子**：窗口内入职并在 Multica 开通账号的员工数（`user.onboarded_at` 落入窗口 或 手动映射中标记已开通）。
- **分母**：窗口内**入职总人数**（外部 LDAP/IDP 的入职事件数；手动模式下为手动录入的入职人数）。
- **数据来源**：LDAP/IDP 同步（推荐）或手动维护（`identity_import` 记录）。Multica 本地库无「入职总人数」来源，故该指标**必须依赖外部或手动数据**。
- **替代口径（未接入 LDAP）**：无法获得入职总人数 → `onboarding_rate = null`，卡片显示引导态；不擅自用 `member.created_at` 造入职口径（会把存量用户/Agent 误判为入职）。

#### 1.4.2 离职权限熔断

- **定义**：窗口内对离职员工执行权限回收（禁用账号/移除工作区成员/吊销 Token）的事件数。
- **数据判定**：`activity_log` 中 action 为 `member_disabled` / `member_removed` / `token_revoked`（需研发在离职流程中落日志；接入 LDAP 后由身份同步任务触发）。
- **成功率** = 熔断成功事件数 ÷ 熔断事件总数；`cutoff_events=0` 时 `null`。
- **数据来源**：LDAP/IDP 同步（推荐）或手动维护。未接入时 `cutoff_events=0`，卡片显示引导态。

### 1.5 部门维度切片（v2.0 新增，条件功能）

- **数据来源**：LDAP/IDP 同步（推荐）或手动映射（`member.department` 字段 + 部门清单配置）。
- **成员归属**：`member` 表新增 `department` 字段（TEXT，外部部门 ID 或手动配置的稳定 ID）；Agent 不归属任何部门。
- **切片范围**：仅 Tab1（活跃度/渗透率/生命周期）与 Tab2 执行漏斗支持 `department_id` 过滤；Tab3/Tab4 不关联部门（Git 按仓库、DORA 按应用，与成员部门无可靠映射，v2.0 不做跨域口径发明）。
- **空态**：所选部门无成员或窗口内无数据 → 对应卡片空态；「全部」= 全局口径。

### 1.6 权限熔断成功率（v2.0 新增，安全合规 KPI）

- **定义**：窗口内权限熔断成功次数 ÷ 应熔断次数 × 100%。
- **应熔断次数**：窗口内触发的离职/降权/异常访问需要回收权限的总次数（LDAP 事件或手动配置）。
- **成功次数**：权限实际被回收且复核通过的次数。
- **数据来源**：LDAP/IDP + Multica 权限系统日志；未接入 → `null`，引导态。

## 2. 模块 2.2 Agent 效能

### 2.1 Agent 执行漏斗 Assign → Execute → Merged（v2.0 更新 Merged 段）

| 阶段 | 定义 | 数据判定 |
| --- | --- | --- |
| **Assign（分配）** | 给 Agent 创建了一次任务 | 窗口内 `agent_task_queue.created_at` 落入窗口的行数（去重前）；Issue 级 Assign 见 §1.2.1 |
| **Execute（执行）** | Agent 实际开始运行 | 该 atq 行 `started_at IS NOT NULL`；窗口按 `started_at` 归属 |
| **Merged（合并）** | 任务的产出被合并 | **二期实现**：`issue_vcs_pull_request` 关联的 PR 中 `state='merged'` 且 `merged_at` 落入窗口，按该 Issue 对应的 atq 行 `started_at` 归属到漏斗链；未接入 VCS 时返回 `null` |

- **漏斗展示**：Assign → Execute → Merged，两段转化率。
- **Merged 口径注意**：同一 Issue 关联多个 PR 时取首个 merged PR；atq 因重试有多行的，Merged 按 Issue 去重（一个 Issue 产出一次合并，避免重复计数）。

### 2.2–2.5 其余 Agent 效能口径（v1.0 保留）

同 v1.0：成功率/失败率、运行时长、技能图谱、协作指数、Blocker。

## 3. 模块 2.3 Git 贡献（v2.0 新增）

### 3.0 Git 数据源总口径

- **首选数据源**：GitCode 线上数据（VCS 连接 + Webhook，见《可行性校验》§7）。
- **当前落地（本地部署，无线上授权/Webhook）**：**本地仓库分析口径**——对工作区配置的本地 Git 仓库（`workspace.repos`）执行 `git log --numstat` 类命令统计提交、作者、增删行，PR 数据以现有 `vcs_pull_request`（含 forgejo/gitea/gitlab 镜像，迁移 216）为准；GitCode 线上 PR 待接入后增量补齐。
- **作者映射**：新增 `vcs_author_mapping(author_email/login, entity_type(member|agent), entity_id)` 表，将提交作者映射到成员或 Agent；未映射作者归入「未归属」。

### 3.1 ELOC（AST 代码当量）

- **定义**：基于 AST 的代码当量，衡量代码产出量。工具链选型待 Leader 确认（建议：Cloc/SCC 统计行数作为兜底 + AST 工具（如 Java/C# 系 `ast-count`、通用 `lizard`）输出当量，见《可行性校验》§7.3）。
- **归属**：按提交作者（经映射）归属到成员/Agent；按提交的 `committed_at` 归属到窗口。
- **人/机对比**：同一窗口内，人产 ELOC 与 Agent 产 ELOC 分别聚合，显示总量比与排名。
- **空值**：工具链未配置 → `null`；无提交 → `0`。

### 3.2 提交质量雷达

| 轴 | 定义 | 数据来源 |
| --- | --- | --- |
| 测试覆盖率 | 窗口/快照时点测试覆盖率（0–1） | 外部扫描工具或 CI 报告导入（覆盖率报告：JaCoCo/istanbul 等） |
| 静态扫描漏洞数 | 严重+高危+中危漏洞总数（0 = 无漏洞） | 静态扫描工具（SonarQube/Semgrep 等）结果导入 |
| 代码重复率 | 重复代码行占比（0–1） | 重复率工具（SonarQube/PMD-CPD 等）结果导入 |

- **快照机制**：外部扫描工具按仓库产出快照（`repo_quality_snapshot(repo, coverage, vulnerabilities, duplication_rate, snapshot_at)`），页面展示**最新快照**并显示「数据截至 {date}」。
- **汇总口径**：选「全部仓库」时取各仓库最新快照的**简单均值**（等权），并回显 `snapshot_at = max(各仓库 snapshot_at)`。
- **空值**：无快照 → 三轴均 `null`，引导态。

### 3.3 代码仓活跃分布

#### 3.3.1 仓库活跃度

- **定义**：窗口内该仓库的提交数 + PR 活动数（创建/合并/关闭各算 1 次）。
- **数据源**：本地仓库 `git log` 统计提交 + `vcs_pull_request`（或 `github_pull_request`）统计 PR。

#### 3.3.2 PR 积压

- **定义**：窗口**期末**（数据快照时点）仍处于 `open` 状态的 PR 数。
- **数据源**：`vcs_pull_request.state='open'`（二期 GitCode 接入后；本地部署无线上 PR 时该值依赖手动导入或 VCS 连接镜像）。

#### 3.3.3 合并周期 MTTM

- **定义**：PR 从创建到合并的时长（`pr_created_at → merged_at`），输出 P50/P95。
- **样本**：窗口内 `merged_at` 落入窗口的 merged PR；`pr_created_at` 早于窗口不裁剪（周期完整计入）。
- **数据源**：`vcs_pull_request` / `github_pull_request`（`state='merged'`、`merged_at`）。
- **空值**：窗口内无 merged PR → `null`。

## 4. 模块 2.4 DORA 效能结果（v2.0 新增）

### 4.0 部署事件定义（核心事实）

- **部署事件**：一次生产/预发布环境的部署记录，字段：`deployment_id`、`app`（应用）、`env`（环境）、`started_at`、`finished_at`、`result(success|failed)`、`recovered_at`（失败后恢复时间）、`issue_ids`（关联 Issue，可空）、`sha`（关联提交，可空）、`reason`（失败原因）。
- **数据来源**：部署流水线数据接入（Webhook/文件导入/手动配置，见《可行性校验》§8）；Multica 本地库**无部署流水线表**。

### 4.1 交付周期（Lead Time）

- **首选口径「Issue→部署」**：Issue 创建（`issue.created_at`）→ 关联部署完成（`deployment.finished_at`）。仅统计有有效关联（部署事件含 `issue_ids` 或 `sha` 反向命中提交并关联 Issue）的样本。
- **替代口径「Issue→Merged」（二期可先行）**：Issue 创建 → 关联 PR merged（`issue_vcs_pull_request` → `vcs_pull_request.merged_at`）。部署流水线未接入时前端自动降级此口径并显示角标（PRD §4.4.1）。
- **输出**：按周 P50/P95 + 样本数；`null`=该周无样本。

### 4.2 部署频率（Deployment Frequency）

- **定义**：窗口内成功+失败部署总数 ÷ 窗口周数（次/周）。
- **数据源**：部署事件表。
- **空值**：无部署事件 → `null`。

### 4.3 变更失败率（Change Failure Rate）

- **定义**：窗口内 `result='failed'` 的部署数 ÷ 窗口内总部署数。
- **空值**：总部署数为 0 → `null`。

### 4.4 MTTR（Mean Time To Recovery）

- **定义**：失败部署的 `failed_at → recovered_at` 时长的中位数 P50（秒）。
- **样本**：窗口内 `recovered_at` 落入窗口且已恢复（`status='resolved'`）的失败部署。
- **空值**：无已恢复失败样本 → `null`。

## 6. 公共维度与筛选

- **project_id**（可选）：所有接口支持 `?project_id=` 按项目过滤；缺省为整个工作区。
- **department_id**（可选，v2.0）：仅 Tab1/Tab2 接口支持；未接入部门数据时传值返回 400。
- **tz**：时区参数，全页统一。
- **days**：窗口天数，默认 30，最大 365；非法值回退默认。
- 全平台 UI 一律复用 `packages/ui`（shadcn + `docs/design.md` token），禁止硬编码样式。
