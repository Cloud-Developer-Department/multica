## 1. 需求背景与目标

需求方（韩维）将方向从「开发者个人用量」升级为「**组织/团队研发效能**」。平台聚焦四大看板：活跃度与渗透（Adoption & Activity）、Agent 效能与贡献（Agent Performance）、Git 贡献与资产（Git Contributions）、DORA 效能结果。

目标：

- 让 Leader/研发团队在**全局**视角看到：人在用、Agent 在产出、协作是否顺畅、工程交付结果如何。
- **全量交付，无分期**：四大看板 + 指标表全部纳入；依赖外部数据源的指标（LDAP/IDP、部署流水线、GitCode 线上数据）须给出**可行替代口径或明确数据接入方案**（本 v2.0 版逐项落地）。
- 数据策略：先做功能，最后统一造演示数据。
- 部署：本地部署（`C:\multica-deploy\multica`，分支 `Equipment_Department_Exploration`），不推 GitHub。

#### 4.3.1 页面说明

- **① KPI 卡组**：活跃仓库数（窗口内有提交或 PR 活动的仓库去重数）；PR 积压（窗口期末仍 open 的 PR 总数）；平均合并周期 MTTM（窗口内 merged PR 的 `pr_created_at → merged_at` 中位数 P50）；ELOC 总量（人机合计，人/机分别显示）。
- **② ELOC 排名**：默认「按人」，可切换「按 Agent」；柱状图或横向排行，每行显示贡献者、ELOC 当量、占总量百分比；**人/机双色**（人=品牌主色，机=辅助色）便于对比。点击贡献者 → 悬浮展示其提交明细（提交数、涉及仓库、时间范围）。
- **③ 提交质量雷达**：仓库下拉单选（默认全部仓库的平均或最新快照），雷达图三轴 = 测试覆盖率（%）、静态扫描漏洞数（越少越好，反轴）、代码重复率（% 越低越好，反轴）；雷达图 hover 显示具体值。数据来自外部扫描工具快照（方案见《可行性校验》§7），无扫描快照时显示「未接入扫描数据」引导态。
- **④ 代码仓活跃分布**：表格行 = 仓库；列 = 活跃度（窗口内提交数 + PR 数）、PR 积压（open PR 数）、合并周期 P50/P95（秒）；列头可排序；行 hover 高亮，点击行 → 下钻该仓库 PR 明细（列表：PR 号、标题、状态、创建/合并时间、作者）。

### 4.5 时间维度切换

- 取值：`7d` / `30d` / `90d`（默认 30d）；可选扩展 `180d`。
- 语义：自然日窗口，`tz` 本地日界；全页所有模块跟随切换、并行全量重查。
- 切换期间：各卡片保留上一窗口数据 + 骨架屏，不整页白屏；返回后原位更新。
- 切换不重置各模块内部切块（如热力图口径、Tab3 的人/机切换）。

### 4.6 部门维度切片（2.1 LDAP 相关，v2.0 新增，条件功能）

- **触发条件**：当 LDAP/IDP 或手动部门映射数据可用时（接口返回 `source_status="ready"`），页面顶部 PageHeader 显示「部门：全部 ▼」筛选器；未接入时隐藏该筛选器，且 §4.1 的 ⑥⑦⑧ 区块显示「数据源未接入」引导态。
- **交互**：选择部门后，Tab1 全部模块（热力图/渗透率/生命周期/熔断成功率）与 Tab2 的执行漏斗按该部门成员子集重新聚合；Tab3/Tab4 不受部门筛选影响（Git/DORA 按仓库与应用维度，与成员部门无映射，v2.0 不做跨域关联，避免口径发明）。
- **部门来源**：LDAP/IDP 同步，或手动维护成员→部门映射（管理入口见《API契约》L2）。部门名以外部系统为准，Multica 仅缓存 `member.department` 字段。
- **空态**：某部门下无成员/无数据时，相关卡片显示对应空态，部门下拉仍可用。

## 5. 模块与交互规则

### 5.1 活跃热力图（Tab1 ②）

- 交互：X 轴日期、Y 轴 0–23 小时，单元格颜色深浅 = 活跃事件数；hover 显示 tooltip「{date} {hour}:00 · {n} 次活跃」。
- 切块：人均 Issue 处理量 / 活跃天数 / 活跃时段（口径见《数据口径说明》§1.1）。
- 点击单元格 → 下钻当日活跃成员列表（悬浮层/弹窗，含成员名、活跃行为计数）。
- 空态（无任何活跃数据）：整图空，显示「窗口内暂无活跃数据」。

### 5.2 Agent 渗透率（Tab1 ④⑤）

- ④ 卡片显示当前窗口两个率：分配占比、Issue 覆盖率。
- ⑤ 趋势图双折线，hover 显示日期与双率。
- 点击⑤ → 跳转/悬浮展示按 Agent 拆分的分配明细（Agent 名、被分配 Issue 数）。

### 5.3 执行漏斗（Tab2 ②）

- 三个阶段横向漏斗；Merged 阶段在 `issue_vcs_pull_request` 有 merged PR 关联前显示**数据源未接入引导态**（虚线 + 「接入 VCS PR 后点亮」角标），接入后正常显示。
- Assign→Execute、Execute→Merged 之间标注转化率。
- 点击各阶段数字 → 下钻对应明细列表。
- 空态（窗口内无 atq 记录）：三个阶段均 0，显示「窗口内暂无 Agent 任务」。

### 5.4 技能积累图谱（Tab2 ③④）

- ③ 折线：按月新技能数（窗口 ≤ 90d 时按月；>90d 按季度）。
- ④ 列表：按复用次数降序 Top10，展示技能名、复用次数、绑定 Agent 数；hover 显示技能简介。
- 点击技能 → 悬浮展示绑定该技能的 Agent 列表。
- 空态：无技能时显示「暂无技能数据」。

### 5.5 人机协作指数与 Blocker（Tab2 ⑤⑥）

- ⑤ 展示互动频率、协作 Issue 占比、Blocker 平均响应时长三个指标。
- ⑥ Blocker 响应时长分布（P50/P95）+ 明细表（Issue、阻塞时间、解除/回应时间、时长）。
- 明细表支持按时长降序、状态筛选（已解除 / 进行中）。
- 空态（无 Blocker 样本）：⑥ 显示「暂无 Blocker 数据（需累积状态变更记录）」；⑤ 仅互动频率有值时正常展示，其余显示 `-`。

### 5.6 ELOC 排名（Tab3 ②）—— v2.0 新增

- Tab 切换「按人 / 按 Agent」：按人按 `issue.creator`/提交作者关联到成员；按 Agent 按提交作者为 Agent（`agent.name` 匹配或 VCS 作者与 Agent 绑定）统计。v2.0 采用**提交作者映射**口径，作者→成员/Agent 映射表（`vcs_author_mapping`）见《数据口径》§3.1。
- 点击排行行 → 悬浮展示该贡献者的提交明细（提交 SHA、时间、涉及仓库、仓库路径）。
- 空态：无 ELOC 数据时显示「ELOC 代码当量工具链未配置」引导态。
- 边界：同一提交同时归属多仓库时按提交去重；作者无法映射到成员或 Agent 时归入「未归属」。

### 5.7 提交质量雷达（Tab3 ③）—— v2.0 新增

- 仓库下拉单选（默认「全部仓库」= 各仓库快照的加权汇总；选具体仓库 = 该仓库最新快照）。
- 雷达图三轴 hover 显示具体数值；数值异常（覆盖率为 0、漏洞数为 0）不改变图形，仅作为数值展示。
- 空态：无任何扫描快照 → 「提交质量扫描未配置」；已配置但目标仓库无快照 → 「该仓库暂无扫描快照」。
- 边界：快照时间戳超出窗口的，仍按最新快照展示并在角标显示快照时间（「数据截至 {date}」）。

### 5.8 代码仓活跃分布（Tab3 ④）—— v2.0 新增

- 表格列：仓库、活跃度（提交数 + PR 数）、PR 积压（open PR 数）、合并周期 P50、合并周期 P95（秒，前端换算为天/小时）。
- 列头可排序（默认按活跃度降序）；行点击 → 下钻该仓库 PR 明细列表。
- 空态：无仓库接入 → 「Git 数据源未接入」；已接入但窗口无活动 → 「窗口内暂无 Git 活动数据」。
- 边界：合并周期仅统计窗口内 `merged_at` 落入窗口的 PR；`pr_created_at` 早于窗口的 PR 仍计入合并周期（周期不受窗口裁剪）。

### 5.9 DORA 交付周期与部署（Tab4 ②③④）—— v2.0 新增

- ② 交付周期趋势默认口径「Issue→部署」，未接入部署流水线时自动降级「Issue→Merged」并显示角标；用户可手动切换，切换即重新拉取。
- ③ 部署频率柱状图：按周聚合部署次数，hover 显示周与次数。
- ④ 变更失败率与 MTTR 折线 + 最近失败明细表（按 MTTR 降序、状态筛选）。
- 空态/引导态见 §4.4.2。
- 边界：部署事件未关联到 Issue 时，不进入「Issue→部署」样本（避免人为关联）；仅计入「部署→Issue」有效关联（部署快照中含 `issue_ids` 或提交 SHA 反向关联）。

### 5.10 用户生命周期与权限熔断（Tab1 ⑥⑦）—— v2.0 新增

- ⑥ 用户生命周期卡：展示入职开通率、离职权限熔断次数。未接入 LDAP 时显示引导态。
- ⑦ 权限熔断成功率卡：熔断成功次数 ÷ 应熔断次数（口径见《数据口径》§1.6）。
- 交互：hover 卡片显示明细口径 tooltip；点击 → 下钻明细列表（成员、事件类型、时间、结果）。
- 空态：无生命周期数据 → 引导态（§7）；有数据但窗口内无事件 → 「窗口内无入职/离职事件」。
