# 与一期设计的一致性微调说明（阶段8）

> 依据：PRD v2.0（CLO-237 阶段7 补充）将 CLO-227 基线更新为「全量交付，无分期」，原二期/三期改为数据源接入阶段标注。
> 目标：CLO-236 v1.0 设计（Tab1 ①–⑤、Tab2）**不推翻**，仅对口径/文案/交互有出入处做增量微调；本文件逐条说明，供前端与 Leader 对照。

---

## 1. Tab Badge 语义更新

| 位置 | v1.0（CLO-236） | v2.0（本阶段） | 原因 |
| --- | --- | --- | --- |
| Tab3 标签 | `Git贡献·二期`（Badge「二期」） | `Git贡献`（去 Badge） | 全量交付无分期；「二期」仅作数据源接入阶段标注，不放 Tab 标签 |
| Tab4 标签 | `DORA·三期`（Badge「三期」） | `DORA`（去 Badge） | 同上 |
| Tab2 漏斗 Merged 段 | `Badge「二期」` + 禁用占位 | `Badge「二期」` 保留为**数据源未接入引导态**角标（`接入 VCS PR 后点亮`），不再是「占位」语义 | PRD §3.4/§5.3：Merged 段由「二期占位」改为数据源未接入引导态 |
| 模块级角标 | 无 | 数据源未接入时各模块 `Badge variant="secondary"`（Git/DORA/LDAP） | API §0.7 `source_status` 契约驱动 |

> 迁移动作：Tab3/Tab4 从 `AnalyticsPlaceholder`（v1.0 `04` 文档 §1/§2）替换为**全量页面设计**（`02`/`03` 文档）。路由 `?tab=git|dora` 不变，仅内容区由占位组件换为真实模块。

## 2. Tab2 执行漏斗 Merged 段（v1.0 D9 → v2.0）

| 维度 | v1.0 | v2.0 |
| --- | --- | --- |
| 视觉 | `border-dashed` 虚线 + 文案「Merged · 二期接入 VCS」+ `opacity-60` | 保持虚线结构，文案改为「Merged · 接入 VCS PR 后点亮」；`Badge variant="secondary"`「二期」→ 语义为**数据源未接入引导态** |
| 交互 | 点击 → Tooltip「二期接入 VCS 后开放」（E10） | 点击 → Tooltip「接入 VCS PR 数据后开放」（E10 文案微调）；`B1.merged_count` 有值（VCS 已接入）→ 正常渲染数值 + 转化率 `merged_ratio` |
| 数据 | `merged_count: null` 恒占位 | `merged_count: null` = VCS 未接入（引导态）；`number` = 已接入（正常态）；`0` = 已接入但窗口无 merged（空态，显示 0） |

> 前端需区分 `null`（引导态）与 `0`（空态）——API 契约 B1 §2 语义；v1.0 将 Merged 恒当占位，v2.0 改为按 `merged_count` 类型三态渲染。

## 4. 空态与引导态语义区分（阶段8 统一规则）

| 语义 | 触发 | 视觉 | 代表模块 |
| --- | --- | --- | --- |
| **数据源未接入（引导态）** | `source_status.ready=false` | `SourceGuideState`（含「前往配置」按钮） | Tab3 全模块 / Tab4 ③④ / Tab1 ⑥⑦⑧ |
| **窗口内无数据（空态）** | `ready=true` 且业务字段 `[]` | `Empty`（无配置按钮） | ELOC `items:[]` / 仓库 `items:[]` / 部署 `trend:[]` |
| **无样本（null → '-'）** | `ready=true` 且字段 `null` | `-` | MTTM `null` / MTTR `null` / 开通率 `null` |
| **数值零（0）** | `ready=true` 且字段 `0` | `0` | 活跃仓库数 0 / PR 积压 0 |

> v1.0 中 Tab3/Tab4 以 `AnalyticsPlaceholder` 占位；v2.0 统一改为「引导态 vs 空态」二分，前端必须严格按 `source_status.ready` 组合判定（API §0.7）。

## 6. 时间维度切换的部门保持

- v2.0：切换时间窗口（7d/30d/90d/180d）时**保留当前部门选择**，重查带 `department_id`（PRD §4.5 + §4.6 组合）；v1.0 无部门维度，此规则为增量。

## 7. 一致性自检结论

| 检查项 | 结论 |
| --- | --- |
| v1.0 已交付 Tab1 ①–⑤ 是否推翻 | 否，原样保留（仅部门筛选时带参重查） |
