## ③ 现存问题与风险

1. **外部数据源未接入是常态，非异常**：Git（二期）/部署流水线与 LDAP（三期）接入前，Tab3/Tab4/Tab1 ⑥⑦⑧ 将长期呈现「数据源未接入」引导态（`source_status.ready=false`）。设计已明确**引导态 ≠ 空态**（引导态含配置入口按钮，空态为窗口内确实无数据），前端必须区分实现，避免把「数据源未接入」误渲染为空态。
2. **交付周期口径自动降级风险**：Tab4 ② 默认「Issue→部署」，未接入部署流水线时自动降级「Issue→Merged」——**降级判断必须由前端依据 `source_status.ready` 触发**（PRD §4.4.1 / API D1），且角标「替代口径：Merged」不可省略，避免口径误导。
3. **ELOC 工具链选型未定**：G1 的 `items` 依赖 AST 工具链输出（可行性 §7.3，行数兜底先行）。设计稿已预留「ELOC 工具链未配置」引导态，前端不应阻塞其他卡片（E13）。
4. **快照数据时效**：质量雷达展示最新快照 + 「数据截至 {date}」角标（E20），快照过期不做硬 TTL；拉取失败展示最近快照 + 失败提示。前端需按 `snapshot_at` 渲染角标。
5. **部门维度跨域不关联**：Tab3/Tab4 不受部门筛选影响（Git 按仓库、DORA 按应用，与成员部门无映射，PRD §4.6）——设计稿明确 PageHeader 部门筛选器仅作用 Tab1/Tab2 接口，避免前端误把 department_id 传给 G/D 接口（未接入传值 → 400）。
6. **空值语义实现成本**：`source_status.ready=false` 时业务字段返回 `null`/`[]`/`0`，前端需按契约 §0.7 组合判定引导态；`null → '-'`、`[] → 空态`、`0 → 数值零` 规则延续 v1.0（`01` 文档 §4）。
